# Security review and deployment guidance

## Scope and result

Reviewed the Express API, all route modules, request schemas, Prisma access patterns, React rendering/API client, environment configuration, Docker Compose, container definitions, Ollama client, prompt builders, output validators, approval transitions, CI, and existing tests at Phase 8 start (`b7a98b0`). This remediation reran the unit, integration, schema, migration, and container checks; live Ollama tests remain blocked. See [reliability results](docs/RELIABILITY.md).

This is an engineering review, not a penetration test or a security certification. The application is **not safe for multi-user or public deployment** until authentication and project-level authorization are implemented. The user chose to defer authentication to a later phase.

## Implemented controls

- Express request bodies remain capped at 1 MB; oversized requests now return 413.
- CORS allows configured frontend origins, selected methods, and `Content-Type`; credentials are not enabled.
- Zod validates request payloads/parameters, and write schemas use explicit fields/strict objects. Prisma is used for parameterized queries; raw queries use tagged templates.
- Existing composite FKs bind related artifacts to exact requirement/project/version records. Approval transitions and version updates use transaction/row locking in earlier phases.
- React renders model/user text through normal escaped JSX; no `dangerouslySetInnerHTML`, `innerHTML`, local/session storage token handling, or custom HTML insertion was found.
- API and frontend return baseline security headers. Requests carry a generated `X-Request-Id`; logs omit query strings, bodies, and prompts.
- General API and AI generation requests have bounded per-process IP limits. The AI cap is shared across generation endpoints in one backend process.
- Ollama response bodies are capped at 512 KB before JSON parse. Existing feature validators separately cap structured AI output and check schema/reference/content constraints.
- Docker Compose host ports bind to `127.0.0.1` for local development.

## Authentication design deferred

No login/session scheme or role model was added. Before the next implementation, agree whether the product needs single-owner local login or an identity provider. A multi-user design should use an established OIDC provider or a carefully scoped session system with secure HttpOnly/SameSite cookies, CSRF protection, account lifecycle controls, and database-backed project membership. Backend authorization should check project membership and roles (`OWNER`, `EDITOR`, `REVIEWER`, `VIEWER`) in every service path; frontend route hiding is not security. The current open API must not be exposed to untrusted networks.

## Deployment precautions

- Put the API behind HTTPS and a trusted reverse proxy; configure proxy trust only for known proxy hops before relying on forwarded client IPs.
- Set unique production `DATABASE_URL`/PostgreSQL credentials via a secret manager. Never reuse `.env.example` values in a deployment.
- Keep PostgreSQL private. Keep Ollama bound to a private/local interface and never publish port 11434 publicly.
- Leave `OLLAMA_ENABLED=false` until a local model has been verified. The app does not need Ollama for startup or deterministic functionality.
- Keep environment files out of source control. Review logs and analysis data retention before handling sensitive requirements.
- Run authenticated security tests and a deployment-specific penetration test after access control is implemented.

## Dependency audit

### SEC-010 investigation (2026-11-20)

- The production audit was rerun with `npm audit --omit=dev`: it reports three HIGH paths, all attributable to one vulnerable package, `effect@3.20.0`; Prisma and `@prisma/config` are the transitive parent path, not themselves the vulnerable package.
- The advisory [GHSA-7589-6fvf-x4pw](https://github.com/advisories/GHSA-7589-6fvf-x4pw) (CVSS 8.7) affects Effect `<=3.22.0`; upstream fixed the `Schema.TemplateLiteral` regex backtracking issue in `effect@3.22.1`. The advisory describes denial of service when untrusted strings are decoded by a template literal with multiple string spans.
- Registry metadata confirms `prisma@7.10.1` depends on `@prisma/config@7.10.1`, which pins `effect@3.20.0`. On this date Prisma's `prev` tag is 7.10.1; the `latest` tag is 8.0.0-rc.34, a major prerelease rather than a compatible security patch. The current 7.10.1 Prisma changelog does not provide a fixed Prisma 7 build.
- Code-path inspection: application request schemas use Zod and do not import Effect. The package is nevertheless present in production because the backend container entrypoint runs `prisma migrate deploy`. Prisma CLI bundles Effect code; its input in this deployment is the checked-in schema/migrations, not API request bodies. The vulnerable path was not demonstrated reachable from HTTP traffic, which reduces the app-facing exposure, but the CLI dependency remains in the production image and its advisory is not resolved. A maliciously crafted schema consumed by the CLI remains a local/CI availability risk.
- No dependency or lockfile change was made. `npm audit fix --force` proposes downgrading to Prisma 6.12.0; that would cross a major version and is not acceptable without compatibility work and explicit approval. Phase 8's attempted override was not reflected in the lockfile. Do not claim a clean audit or public-deployment readiness.

Run `npm audit --omit=dev` and `npm audit` before release, record registry/audit timestamp and findings, and address production vulnerabilities by targeted upgrades. A clean audit does not replace source review.

## Local LLM verification update (2026-11-20)

Ollama 0.40.16 with `qwen2.5:3b-instruct` was exercised locally. Prompt version 1.2.0 redacts credential-like markers and unsupported UUIDs from supplied free-text context; the output guard independently rejects echoed markers and unsupported UUID references. In the latest 14-case run, planted-marker echo was 0/14, but only 11/14 outputs passed full validation. This is limited evidence for the selected synthetic probes, not proof of prompt-injection resistance. Three invalid outputs were rejected; the three downstream generators also safely rejected invalid outputs. See `docs/AI_EVALUATION.md`.
